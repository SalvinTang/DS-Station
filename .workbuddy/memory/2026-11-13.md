# 2026-11-13

## DS Station 内存优化分析（只分析，未改代码）

产出：`docs/内存优化方案.md`

关键结论：
- 常驻 5 个渲染进程，其中 GuideWindow / TrayMenuWindow 启动即建（`main.ts:221-222`），几乎不可见，占 120–160MB。
- `index.ts:78-81` 三个全局 switch + `main-window.ts:139` 的 `backgroundThrottling:false` → 隐藏页面永不休眠，是内存不回落的主因。
- 流式链路三重浪费：150ms 读整条 `outerHTML`（`page-driver.ts:552`）、推送不判重（`:564`）、渲染端全量 `innerHTML` 重建（`markdown.ts:479-498`）。
- `waitForAnswerChange` 每 150ms 序列化全部历史回答（`listAnswers`）。
- 回收时机不在「关面板」，而在「会话被丢弃」：新对话 / resetAfterMinutes 超时 / 退出登录。因为关闭时面板仍是 content 态。
- 「打开时才创建页面」单独做收益≈0：面板启动即打开（`startup.ts:63`）。
- 红线：CDP、renderer-process-limit、定时 reload。
- 改造要点：PageKeeper + `withPage`，避免 `DeepSeekPage` 长持 `view` 引用（`page-driver.ts:57`）导致静默失败。
