帮我把下面这段同步的 Python 代码改成 async 版本，注意要控制并发数。
DS
▶ 已深度思考（用时 8 秒）

用 asyncio.Semaphore 控制并发是最直接的做法。

python⧉ 复制
import asyncio, aiohttp

async def fetch(session, url, sem):
    async with sem:                      # 并发闸门
        async with session.get(url) as resp:
            return await resp.text()

async def main(urls, limit=5):
    sem = asyncio.Semaphore(limit)
    async with aiohttp.ClientSession() as s:
        return await asyncio.gather(*(fetch(s, u, sem) for u in urls))

要点：Semaphore 保证任意时刻最多 5 个请求在飞，其余排队等待。

asyncio.gather 里某个请求抛异常了，其他请求会怎样？
DS
▶ 已深度思考（用时 5 秒）

默认情况下 gather 会立即向外抛出第一个异常，但不会取消其他已经启动的协程——它们会继续跑完，只是结果没人接。

要「一个失败就全部取消」，用 asyncio.TaskGroup（3.11+）或手动 task.cancel()。

那 TaskGroup 里想保留其它结果怎么做？
DS

TaskGroup 的设计就是「要么全成、要么全废」，所以它不给你收集部分结果的机会。

要保留已完成的结果，得退回到手动管理：每个任务各自 try/except 兜住异常并把 (结果, 异常) 一起返回，外层再统一汇总。

待你拍板的问题

这 6 个问题的答案会直接决定代码怎么写。下面每条都附了我的建议。

1. 快速窗口用哪个方案 最关键

方案A（面板里放真实网页）：流式输出、附件、深度思考、联网搜索全部开箱可用，几乎不会坏。代价是每个面板实例占 250–500MB 内存，且面板里是一个独立的新对话，看不到主窗口那个对话。

方案B（App 自绘输入框）：轻、快、能和主窗口对话无缝衔接。代价是要注入 DOM 读内容、模拟输入，DeepSeek 一发版就可能碎掉，附件支持也更麻烦。

我的建议：先做方案A（稳、能马上用），把方案B作为后续增强。

2. 快捷窗口要显示哪个对话 需明确

你最初说「显示当前对话内容」，但说明书 §7 的示意图里只有一个输入框。

由于 DeepSeek 网页版没有 URL 路由、会话 id 只存在内存里，第二个网页实例无法自动变到主窗口正在看的那个对话。

选项：① 面板是独立的新对话；② 面板里能切换到主窗口的对话（需额外做同步，更脆）。

3. 快捷键定 ⌥Space 可以吗 待确认

⌘Space 被 Spotlight 占用，物理上注册不了。⌃Space 是输入法切换。

建议默认 ⌥Space，设置里可改。

4. 注入 CSS 算不算违反原则 待确认

说明书 §5 说「不要注入 JavaScript 修改 DOM」，但 §6 又要求把界面调得更像原生 App —— 这两件事有冲突。

我的建议：允许纯 CSS 注入（隐藏推广条、限制正文宽度、改滚动条），不做 DOM 结构改动、不读页面数据。CSS 坏掉最多是丑，不会让功能失效。

5. Cloudflare 是生死线 先验证

有报告称 chat.deepseek.com 的人机验证在嵌入式 WebView 里会无限循环卡死；且运行中改 User-Agent 会让验证立即失效。

所以第一步不是写功能，而是：起一个 Electron 窗口加载 chat.deepseek.com，验证能登录、重启后登录态还在。这一步不过，后面全白做。

6. 登录方式要提前说明 注意

Google 账号登录在嵌入式 WebView 里基本走不通（Google 会拦截，报 disallowed_useragent）；跳系统浏览器登录后 cookie 也回不来。

手机号验证码、邮箱密码、微信扫码都正常。建议在首次启动的引导页直接写明，避免用户卡住。

7. 内存占用 可接受

两个完整 DeepSeek 网页实例 ≈ 500MB–1GB。

优化：快速窗口的页面首次呼出时才创建（懒加载），面板连续 N 分钟没用可选择性释放。
