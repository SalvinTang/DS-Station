# DS Desktop · HTML 产品原型

这是给《DS Desktop 产品计划文档 v1.0.0》配的可交互原型，**不是真实代码**，只用来看产品形态、确认设计方向。

## 怎么打开

直接双击 `index.html`，或在浏览器里打开：

```
open "/Users/salvin/Salvin/VibeCoding/DS Desktop/HTMLdemo/index.html"
```

无外部依赖，离线可用。

## 五个页面

| 标签 | 内容 |
|---|---|
| ① 主窗口 | 完整 DeepSeek 网页版 + 标题栏。打开右上角「显示标注」可以看到这个外壳对页面做了哪些调整 |
| ② 快速窗口 · 方案A | 面板里放**真实的 DeepSeek 网页**（第二个 WebContentsView）。左：空状态，右：对话中 |
| ③ 快速窗口 · 方案B | App **自绘的轻量输入框**，对话内容靠注入主窗口读取 |
| ④ 设置 | 含 ⌘Space 注册不了的警告 |
| ⑤ 待确认清单 | 8 张卡片，每条都附了我的建议 |

## 快捷键（原型里）

- `⌥ + Space` —— 切到快速窗口（模拟真实 App 的呼出）
- `Esc` —— 回到主窗口
- 右上角「深色」可以看暗色模式

## 最关键的两个取舍

**快速窗口到底长什么样？** 这是方案 A 和方案 B 的分水岭：

- **方案 A**：面板里就是那个真实的 DeepSeek 网页，只是被压缩了尺寸、隐藏了侧栏。流式输出、附件、深度思考、联网搜索**全部开箱可用**，而且几乎不会因为 DeepSeek 改版而失效。代价是：① 每个实例 250–500MB 内存；② 面板里是一个**独立的新对话**，看不到主窗口正在看的那个对话。
- **方案 B**：面板是 App 自己画的，所以能做得又快又轻、还能和主窗口的对话无缝衔接。代价是必须**注入 DOM 去读内容、模拟输入**，DeepSeek 前端一发版就可能碎掉，附件支持也更麻烦。

> 我的建议：**先做 A**（稳、能马上天天用），B 作为后续增强。

## 原型里发现、说明书里没有的坑

1. **⌘Space 注册不了** —— 被 macOS Spotlight 独占，`globalShortcut.register()` 直接返回 `false`。说明书 §7 / §14 / §20 三处还给的不一致。建议默认 **⌥Space**。
2. **快速窗口"直接加载网页" ≠ 说明书 §7 的那个输入框示意图** —— 一个完整 SPA 塞进 620×200 的窗口，出来的是被压扁的完整网页。要变成示意图那样，只能注入 CSS 隐藏侧栏，或者把主窗口那个 WebContentsView 搬进面板。
3. **Cloudflare 是唯一的生死线** —— 说明书完全没提。有报告称 chat.deepseek.com 的人机验证在嵌入式 WebView 里会无限循环；而且**运行中改 User-Agent 会让验证立即失效**。第一步应该先验证能不能登录、重启后登录态还在。
4. **Google 登录在嵌入式 WebView 里基本走不通** —— Google 会拦截（`disallowed_useragent`），跳系统浏览器登录后 cookie 也回不来。手机号/邮箱/微信扫码都正常，建议首启引导里写明。
5. **§5「不要注入 JS 改 DOM」与 §6「让界面更像原生 App」有冲突** —— 建议放宽为「允许纯 CSS 注入，不做 DOM 结构改动、不读页面数据」，CSS 坏掉最多是丑，不会让功能失效。
6. **两套网页实例 ≈ 500MB–1GB 内存** —— 建议快速窗口懒加载（首次呼出才创建）。
7. **缺少单实例锁** —— 双开会让两个进程争抢同一份 `persist:` 分区，可能损坏登录态。
8. **§11 说「不需要 Renderer」，§15 却有设置界面** —— MVP 建议设置直接放 macOS 原生菜单，少写一整套 Renderer。
9. **章节编号缺 §19**（从 18 跳到 20）。
